## 1. 왜 다시 짰나 (기존 8장 순서의 문제)

| 번호 | 기존 순서의 문제 | 생기는 일 | 이 문서의 해결 |
|---|---|---|---|
| ① | "0단계: 기준 수치 먼저" 인데, 기준선(아무 조건에서 닫는 비율)을 모르면 %p 기준도 표본 수도 정할 수 없음 | 근거 없는 숫자로 사전 등록하거나, 결과를 본 뒤 숫자를 정하게 됨 | 기술 검증(P2)과 파일럿(P6)을 사전 등록(P7) **앞**에 둠. 파일럿 데이터는 본 분석에서 제외 |
| ② | 목업과 실행 장치가 "1단계 구현" 한 줄에 뭉쳐 있음 | 조건 간 화면이 정말 표시만 다른지, 에이전트가 팝업을 실제로 봤는지 검증 없이 데이터를 쌓게 됨 | 목업(P3)과 실행 장치(P4)를 나누고 각각 통과 기준을 둠 |
| ③ | 행동을 에이전트 로그(말)로 판정하는 구조 | 에이전트가 "취소했다"고 말해도 실제로는 다를 수 있음 | **목업 사이트의 이벤트 로그를 행동 판정의 기준**으로 함 (P3) |
| ④ | 행동 분류, 특히 "보고 여부" 판정 기준과 검증 절차가 없음 | 판정자가 조건을 알고 판정하면 편향이 섞임 | 코드북, 조건 가림 판정, 일치도 기준을 미리 정함 (P5) |
| ⑤ | API 비용 산정이 "설계 후"로 미뤄져 있음 | 본 실행 중간에 예산이 바닥나 표본이 모자람 | 기술 검증과 파일럿에서 실측하고 예산 상한을 정함 (P2, P6, P8) |
| ⑥ | 모델 버전 고정, 실행 날짜 기록 규칙이 없음 | 같은 별칭이 중간에 다른 모델로 바뀌면 결과를 비교할 수 없음 | 날짜가 들어간 전체 모델 ID 기록, 본 실행은 짧은 기간에 몰아서 (P4, P8) |
| ⑦ | 분석 방법은 정하지만 분석 **코드**를 언제 쓰는지 없음 | 결과를 본 뒤 코드를 쓰면 사전 등록이 사실상 무의미해짐 | 가짜 데이터로 분석 스크립트를 미리 돌려 보고 함께 고정 (P7) |
| ⑧ | 선생님 검토 시점이 "설계가 끝난 시점"으로 모호 | 너무 이르면 검토할 게 없고, 너무 늦으면 고칠 수 없음 | 사전 등록 고정 **직전**으로 못 박음 (P7) |
| ⑨ | 설계가 바뀌었을 때 어디로 되돌아가는지 규칙이 없음 | 바뀐 설계로 일부만 다시 하고 나머지는 옛 설계 그대로 남음 | 되돌아가기 규칙을 둠 (4장) |

### P5. 측정·판정 체계

- **목적**: 행동과 보고 여부를 **누가 판정해도 같은 결과**가 나오게 함.
- **할 일**
  1. 행동 축(적용/닫기·취소/무시/질문)은 사이트 이벤트 로그로 **자동 판정**하는 규칙 작성
  2. 텍스트 판정 항목(보고 여부, "AI" 언급 여부) 코드북 작성: 정의, 포함·제외 예시, 애매한 경우 처리
  3. 판정 방법 결정: 사람 판정 / LLM 판정 + 사람 표본 검증
  4. 판정 시 **조건 정보를 가림** (팝업 문구도 가린 텍스트로 판정)
  5. 일치도 기준 정함 (예: 두 판정 간 Cohen's κ 0.8 이상)
  6. 직접 만든 예시 텍스트로 판정 절차 시험
- **산출물**: `docs/codebook.md`, 판정 스크립트
- **게이트**
  - [ ] 예시 텍스트로 일치도 기준 충족
  - [ ] 자동 판정 규칙이 P3 로그 형식과 맞음

### P6. 파일럿

- **목적**: 본 실행 전에 **작동 여부, 행동 분포, 비용**을 실측함. 효과 크기를 보는 단계가 아님.
- **할 일**
  1. 조건당 5~10회 실행 (사전에 예상 비용을 사용자에게 알리고 승인받음)
  2. 확인 항목: 정상 작동률, 팝업이 관찰에 들어간 비율, 행동 분포, 1회 비용·시간
  3. 파일럿 보고서 작성
- **산출물**: `data/pilot/`, `docs/pilot-report.md`
- **게이트**
  - [ ] 정상 작동률 90% 이상
  - [ ] 팝업이 관찰에 들어간 비율 100% (아니면 P3/P4로)
  - [ ] **한 행동이 90%를 넘지 않음**. 넘으면 천장·바닥 효과이므로 P1로 돌아가 유형 또는 지시 강도 조정
  - [ ] 본 실행 예상 비용 산출
- **주의**: 파일럿 데이터는 **본 분석에 넣지 않음**. 파일럿에서 조건 간 차이를 보고 기준을 정하지 않음 (기준선 비율만 씀).

### P7. 사전 등록 고정

- **목적**: 결과를 보기 전에 판정 기준과 분석 방법을 바꿀 수 없게 고정함.
- **할 일** (`docs/preregistration.md`에 작성)
  1. 가설(양방향), 조건, 1차 지표(예: "AI 생성" vs "자동 생성"의 적용 비율 차이)
  2. 표본 수: 파일럿 기준선 비율로 검정력 계산
  3. 검정 방법, 유의수준, 판정 기준(양방향 %p)
  4. 제외 규칙, 중단 규칙(예산 상한, 오류율 상한)
  5. 탐색적 분석 목록 (1차 지표가 아닌 것은 여기 적은 것만, "탐색적"으로 표시)
  6. 분석 스크립트를 `analysis/`에 작성하고 **가짜 데이터**로 실행해 결과표가 나오는지 확인
  7. 교육과정 선생님 검토 (선택이지만 이 시점이 가장 효과적)
  8. git 태그 `prereg-v1` 생성, 하네스에 `docs/preregistration.md`와 `analysis/` 수정 금지 규칙 추가
- **산출물**: `docs/preregistration.md`, `analysis/`, 태그 `prereg-v1`
- **게이트**
  - [ ] 가짜 데이터로 분석 스크립트가 끝까지 돌아감
  - [ ] 태그 생성, 수정 금지 규칙 추가됨
  - [ ] 사용자 승인

### P8. 본 실행

- **목적**: 사전 등록대로 데이터를 모음.
- **할 일**
  1. 총 예상 비용 제시 → 사용자 승인
  2. 짧은 기간에 몰아서 실행 (모델 변동 방지). 실행 순서 무작위
  3. 실행 중에는 **작동 지표만** 봄 (오류율, 비용). 조건별 결과는 보지 않음
  4. 원본은 `data/raw/`에 쓰기만 함 (수정·삭제 금지)
- **산출물**: `data/raw/`, 실행 일지
- **게이트**
  - [ ] 계획 표본 수 채움 (제외 규칙 적용 후 기준)
  - [ ] 제외한 실행과 이유가 기록됨

### P9. 분석

- **목적**: 고정된 방법 그대로 결과를 냄.
- **할 일**
  1. `prereg-v1` 태그의 분석 스크립트를 **그대로** 실행
  2. 사전 등록 밖의 분석은 "탐색적" 절로 분리해 적음
  3. 결과 보고서 작성 (효과 없음도 그대로 보고)
- **산출물**: `docs/results-stage1.md`, `data/processed/`
- **게이트**
  - [ ] 결과표가 태그 시점 스크립트로 재현됨

### P10. 판정과 분기

- **목적**: 사전 등록 기준대로 다음 경로를 정함.
- **할 일**: research-notes.md 8장의 분기표(2단계 논문 경로 / 3단계 포트폴리오 경로 / 중단)대로 판정하고 기록함.
- **산출물**: `docs/decisions/`에 판정 기록
- **이후**: 2단계로 가면 P1~P9를 확장 설계로 한 번 더 돎 (유형 1·2, 분야, 모델 3종 이상, H3 하위 가설).

## 4. 되돌아가기 규칙

| 바뀐 것 | 돌아갈 단계 | 다시 해야 하는 것 |
|---|---|---|
| 조건, 유형, 팝업 문구, 화면 흐름 | P1 | P3 동등성 검사, P4 실제 모델 3회, P6 파일럿 |
| 실행 방식(도구) | P2 | P4 전체, P6 |
| 목업 코드 | P3 | 동등성 검사, 직접 클릭 검사, P6 |
| 실행 프롬프트, 가상 사용자 답변 | P1 (명세서 수정) | P4 실제 모델 3회, P6 |
| 판정 코드북 | P5 | 일치도 시험 |
| P7 이후 무엇이든 | **원칙적으로 금지** | 꼭 필요하면 사전 등록 "변경 기록"에 날짜, 이유, 데이터 열람 여부를 적고, 이미 모은 본 데이터는 새 설계와 섞지 않음 |

- 파일럿을 다시 하면 이전 파일럿 데이터는 `data/pilot/`에 날짜별로 남겨 두되, 새 기준선 계산에는 새 파일럿만 씀.
