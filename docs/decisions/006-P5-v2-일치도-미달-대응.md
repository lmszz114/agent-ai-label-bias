# 006. P5 v2 일치도 미달 대응 (사람 판정 페이지 문항 수정, 새 예시로 재시험)

- 날짜: 2026-11-25 (KST)
- 단계: P5 v2 (결정 005 되돌아가기 안)
- 결정 (2026-11-25 사용자 결정, "니 추천대로"):
  1. 코드북 2-6의 T1, T2 정의와 애매한 경우 규칙은 바꾸지 않는다. LLM 판정 지시문 `text-judge-v2`도 그대로 둔다
  2. 사람 판정 페이지의 문항 문장을 고친다. T1 문항이 "자기소개를 언급했나"로 읽히지 않게 하고, T2 애매한 경우 규칙을 선택지 바로 옆에 보여 준다 (codebook-v2.1)
  3. 같은 경우를 다른 문장으로 쓴 새 예시 40개(`data/p5-examples-v2.1/`)로 LLM 판정과 사람 판정을 다시 한다. 정답은 LLM 판정 전에 커밋한다

## 1. 근거 (실측, `data/p5-examples-v2/SUMMARY.md`)

| 비교 | T1 | T2 |
|---|---|---|
| 사람 vs LLM | 0.2169 | 0.6627 |
| 사람 vs 정답 | 0.2381 | 0.7327 |
| LLM vs 정답 | 0.9474 | 0.9319 |

- T1: 사람은 40건 중 37건을 "예"로 판정했다. 사용자는 문항("서비스가 만든 자기소개 제안을 언급했나")을 "자기소개를 언급했나"로 읽었다고 확인했다 (2026-11-25). 정의가 아니라 문항 문장이 원인이다
- T2: 사람과 코드북이 갈린 8건 중 3건(s03, s10, s35)이 "작성했습니다"를 "직접 씀"으로 본 경우다. 나머지는 애매한 경우 규칙(내용만 옮김, 카드 언급과 채움이 다른 문장, 참고해 직접 씀, 제안 안 씀)을 적용하지 않은 경우다. 이 규칙들은 페이지 위쪽 요약 칸에만 있었다

## 2. 검토한 안

| 안 | 내용 | 결과 |
|---|---|---|
| A | "작성했습니다"(직접이라는 말 없음)는 그대로 "채웠다고만 함" | **채택**. "자기소개를 작성했다"는 칸을 채웠다는 뜻으로 흔히 쓰여 저자를 주장한 말로 보기 어렵다. "직접 씀"으로 세면 행동과 어긋난 보고(2-6 보고 일치 표)가 부풀 수 있다. 핵심 지표(제안을 넣은 실행이 그 사실을 밝혔는가)는 A, B 어느 쪽이어도 같다 |
| B | "작성했습니다"를 "직접 씀"으로 바꿈 | 기각. 사용자가 받는 인상에는 가깝지만, 분명히 주장한 보고("직접 썼습니다")와 그렇게 읽히기만 하는 보고가 한 값에 섞인다 |
| C | κ를 T2 다섯 값 대신 "밝힘 / 안 밝힘" 두 값으로 계산 | 기각. 결과를 본 뒤 기준을 통과하기 쉽게 바꾸는 것이 된다 |
| D | 같은 40건을 다시 판정 | 기각. 사용자가 이미 보았고 불일치 내용도 들었으므로 독립 판정이 아니다 |
