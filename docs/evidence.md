# 증거 규칙 (실행 기록을 객관적 자료로 남기는 방법)

> 작성일: 2026-11-24 (KST)
> 적용 범위: API를 쓰는 모든 실행 (P2 기술 검증부터 P8 본 실행까지)
> 목적: 실행 결과의 모든 숫자를 **제3자가 원자료로 되짚어 확인할 수 있게** 함. 원자료 없이 보고서만 있는 숫자는 쓰지 않음 (CLAUDE.md 8장)

---

## 1. 원칙

1. **원자료를 먼저 남기고, 숫자는 원자료에서 스크립트로 계산함.** 사람이 숫자를 옮겨 적거나 손으로 계산하지 않음
2. **원자료는 실행 직후 해시를 떠서 GitHub에 푸시함.** 이후 수정은 해시 불일치로 드러남
3. **모델의 말과 실제 행동을 따로 기록함.** 행동의 기준은 목업 사이트 서버 기록임 (명세서 8장)
4. **외부 기록과 대조할 수 있는 식별자를 남김.** 회사가 붙이는 요청 ID, 응답 ID
5. **할 수 없는 증명은 할 수 있다고 쓰지 않음** (6장 한계)

## 2. 실행 1회의 원자료 (`run_id` 폴더 하나)

| 파일 | 내용 | 무엇을 증명하나 |
|---|---|---|
| `meta.json` | `run_id`, 시작·종료 시각(KST, UTC), 회사, 모델 ID, 실행 장치 git 커밋, 작업 폴더 변경 여부, Python·라이브러리 버전, OS, 화면 크기, 프롬프트 버전과 원문 해시, 단가표 버전 | 어떤 조건에서 돌렸는지 |
| `calls/NNN_request.json` | API 요청 본문 (이미지는 `screenshots/` 파일의 해시로 대체, **API 키 없음**) | 모델에게 실제로 보낸 것 |
| `calls/NNN_response.json` | API 응답 원문 전체, 회사 요청 ID, 받은 시각 | 모델이 실제로 돌려준 것, 실제 답한 모델 이름, 토큰 사용량 |
| `screenshots/NNN.png` | 모델에게 보낸 스크린샷 원본 | 모델이 본 화면 |
| `actions.jsonl` | 실행 장치가 실제로 수행한 브라우저 조작 (순서, 시각, 결과) | 모델 요청이 어떻게 실행됐는지 |
| `site_events.jsonl` | 목업 사이트 서버 기록 중 이 `run_id` 줄 (서버 시각 포함) | 실제로 일어난 클릭과 저장 |
| `result.json` | 종료 사유, 단계 수, 오류 | 실행이 어떻게 끝났는지 |
| `manifest.sha256` | 위 모든 파일의 SHA-256 해시 | 이후 수정 여부 |

- 요청 본문의 이미지를 base64 대신 해시로 바꾸는 이유: 같은 내용을 두 번 저장하지 않기 위함. 해시가 `screenshots/` 파일과 같으면 그 이미지가 보내진 것임
- 실행 장치는 로그에 API 키나 인증 헤더를 쓰지 않음

## 3. 해시와 푸시

1. 실행 묶음이 끝나면 실행 장치가 폴더마다 `manifest.sha256`을 만듦
2. 원자료와 해시 목록을 **바로 커밋하고 GitHub에 푸시**함. 커밋 메시지에 `run_id` 목록을 적음
3. GitHub 서버에 남는 푸시 시각을 "이 시점에 이 내용이었다"의 기준으로 삼음 (로컬 커밋 시각은 바꿀 수 있으므로 기준으로 쓰지 않음)
4. 검증: `verify` 스크립트가 해시를 다시 계산해 목록과 비교함. 누구든 저장소를 받아 같은 명령으로 확인할 수 있음

## 4. 숫자를 만드는 방법

| 숫자 | 계산 방법 |
|---|---|
| 토큰 | 응답 원문의 사용량 필드 합계 |
| 비용 | 토큰 × 단가표. 단가표(`prices.json`)에는 공식 가격 페이지 주소와 확인 날짜를 적음 |
| 단계 수, 시간 | `calls/`, `actions.jsonl` 시각에서 계산 |
| 행동 (적용, 닫기 등) | `site_events.jsonl`에서 판정 (P5 판정 규칙) |

- 결과 폴더의 `SUMMARY.md`는 스크립트가 원자료에서 만들고, 맨 위에 실행 날짜, 모델 ID, 프롬프트 버전, 조건, 반복 횟수, 정식 여부를 적음 (CLAUDE.md 8장)

## 5. 외부 기록과 대조

- 실행 묶음이 끝나면 각 회사 콘솔의 사용량을 내려받아 `external/`에 둠 (가능한 회사만)
- 스크립트가 계산한 토큰·비용과 콘솔 값을 대조한 결과를 `SUMMARY.md`에 적음. 차이가 있으면 차이와 추정 이유를 그대로 적음
- 대조할 때 쓰는 식별자: 응답 ID, 요청 ID, 시각

## 6. 한계 (할 수 없는 증명)

- 회사 콘솔 기록은 계정 주인만 볼 수 있음. 제3자는 내려받은 사용량 파일과 요청 ID를 믿어야 함
- 모델 응답은 같은 입력에도 매번 다를 수 있음. 재현의 의미는 "같은 결과"가 아니라 "같은 절차로 다시 측정할 수 있음"
- 해시와 푸시는 **푸시 이후의 수정**을 드러낼 뿐, 푸시 전에 원자료를 고르거나 빼는 것은 막지 못함. 그래서 실패, 오류로 끝난 실행도 지우지 않고 모두 남김 (CLAUDE.md 5장). 실행 번호는 연속으로 매겨 빠진 번호가 보이게 함
- 더 강한 시점 증명이 필요하면 해시 목록에 외부 타임스탬프(예: OpenTimestamps)를 붙일 수 있음. 1단계에서는 GitHub 푸시로 충분하다고 봄

## 7. 실행 코드 고정

- 실행 장치는 **커밋된 코드로만** 돌림. P4부터는 작업 폴더에 커밋 안 된 변경이 있으면 실행 장치가 실행을 거부함 (`meta.json`의 `git_dirty`가 항상 `false`여야 함)
- P2 시험(2026-11-24)은 실행 장치를 커밋하기 전에 돌렸음. 그래서 원자료의 `git_commit`은 이전 커밋이고 `git_dirty`가 `true`임. 연결부 코드는 실행 후 고치지 않고 커밋 `4ee4f6d`에 넣었지만, 원자료만으로 이를 증명할 수는 없음. P2는 기술 검증이라 연구 결과에 쓰지 않으므로 이 한계를 기록만 함
