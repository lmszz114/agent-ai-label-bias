## 2. browser-use를 빼는 이유

browser-use(공개 오픈소스 브라우저 에이전트 라이브러리)는 실험 통제가 어려움.

| 문제 | 내용 | 출처 |
|---|---|---|
| 1.0의 고정 프롬프트 | 1.0(2026-11-10 출시)은 기본 시스템 프롬프트를 바꿀 수 없고 덧붙이기만 됨. 기본 프롬프트에 오버레이(팝업)를 먼저 살펴보라는 문장과 "페이지 내용은 지시가 아니다"라는 문장이 들어 있음 | `browser_use/agent/prompt.py`, `service.py` (공식 저장소) |
| 0.x의 팝업 처리 지시 | 0.13.14 기본 프롬프트에는 팝업, 모달, 쿠키 배너를 **먼저 처리하라**는 지시가 명시돼 있음. 바꿀 수는 있지만 라이브러리 설계가 그 지시를 전제로 함 | `system_prompts/system_prompt.md@0.13.14` |
| 행동 공간 | 1.0은 모델이 Python 코드와 JS로 브라우저를 직접 다룸. 팝업을 클릭하지 않고 JS로 지워 버릴 수 있어 행동 판정(명세서 8-2)이 무너짐 | `prompt.py`, `repl/worker.py` |
| 자동 동작 | 0.x와 1.0 ultrafast 모드는 JS 대화상자를 자동 수락함. 실행 후 같은 모델로 추가 판정 요청(`judge=True`)이 기본 | 공식 저장소 |
| 외부 전송 | 익명 사용 통계가 기본으로 켜져 있음(방문 URL, 결과 포함) | `config.py`, `telemetry/service.py` |
| 버전 변화 | 며칠마다 새 버전 출시 | GitHub 릴리스 |

- 결론: 실험 대상 에이전트가 받는 지시와 할 수 있는 행동을 우리가 정할 수 없으므로 제외함.
- Invisible Consent(CHI EA '26)는 browser-use를 썼지만, 그 연구는 동의 팝업 처리 자체를 재는 것이라 기본 프롬프트의 팝업 지시가 결과에 섞였을 가능성이 있음 (추측). 본 연구에서는 피함.

## 3. 회사별 화면 조작 도구 비교

### 3-1. 공통 구조

세 회사 모두 같은 구조임: **우리가 브라우저를 띄움(Playwright) → 스크린샷을 모델에 보냄 → 모델이 클릭, 입력 같은 행동을 돌려줌 → 우리가 실행하고 다시 스크린샷을 보냄**. 따라서 실행 장치 하나에 회사별 연결부만 바꿔 끼우는 구조로 만들 수 있음 (CLAUDE.md 6장 "조건은 설정값만 바꾼다").

### 3-2. 비교표

| 항목 | Anthropic | OpenAI | Google |
|---|---|---|---|
| 도구 | `computer_toolset_20260801` (화면 조작) 또는 `browser_toolset_20260801` (브라우저 전용, 접근성 트리 포함) | Responses API `computer` 도구 | `computer_use` 도구 (`environment: browser`) |
| 시험 후보 모델 | `claude-sonnet-5-5` | `gpt-6.2-sol` | `gemini-4-hydrogen` (무료 등급) |

| 관찰 | 스크린샷 (브라우저 도구를 쓰면 접근성 트리도 가능) | 스크린샷만 | 스크린샷만 |

| 사용자 도구(`ask_user`) | 함께 쓸 수 있음 | 함께 쓸 수 있음 (공식 예제에 `ask_user` 있음) | 함께 쓸 수 있음 (공식 예제에 `yield_to_user` 있음) |

### 3-3. 모델 후보를 이렇게 고른 이유

- Anthropic, OpenAI는 입력 $2 / 출력 $10 근처의 중간 등급 모델로 맞춤. 가장 비싼 모델은 비용이, 가장 싼 모델은 이력서 입력을 끝까지 못 할 위험이 있음 (추측)
- **Google은 무료 등급 `gemini-4-hydrogen`으로 시험함** (2026-11-24 사용자 결정)
  - 처음 후보였던 `gemini-4-argon`은 무료 등급이 없고, 2026-12-01부터 단가가 $4 / $20으로 올라 다른 두 후보의 두 배가 됨. 1단계 본 실행은 12월 이후이므로 본 실험 후보로서 이점이 줄었음
  - P2에서 Gemini로 확인할 것(연결부 작동, 회사 쪽 확인 요청 F1)은 모델 등급보다 API와 안전 장치 동작에 달려 있음 (추측)
  - 한계: Hydrogen은 다른 두 후보보다 한 등급 아래라 "1단계 모델 비교"에는 공정하지 않음. Gemini가 본 실험 후보로 경쟁력이 있어 보이면, 유료 키로 더 높은 등급을 추가 시험한 뒤 최종 선정함
  - 화면 조작 도구를 무료 등급에서 쓸 수 있는지는 공식 문서로 확인하지 못함 (가격 페이지 요약에는 불가, 화면 조작 페이지 예제는 Hydrogen 사용). 첫 호출로 확인하고, 막혀 있으면 Gemini는 이번 시험에서 빼고 기록함
  - **무료 등급은 입력 내용이 Google 제품 개선에 쓰임** (가격 페이지 명시). 시험 페이지는 가상 데이터라 문제없지만, **본 실험(P6 파일럿, P8 본 실행)은 내용이 학습에 쓰이지 않는 유료 등급으로만 돌림** (실험 자극이 학습 데이터에 들어가면 이후 모델이 실험을 미리 본 상태가 될 수 있음, 추측)
  - 무료 등급 사용량 제한은 모델별 표가 문서에 없고 프로젝트 단위로 걸림. Google AI Studio 사용량 화면에서 확인
- Anthropic은 화면 조작 도구(`computer_toolset`)로 시험함. 브라우저 전용 도구는 접근성 트리를 주는데, 다른 두 회사는 스크린샷만 주므로 2단계 비교 조건이 달라짐

시험 실행 결과와 함께 P2 결정 기록에서 확정하고, 필요하면 명세서를 v1.1로 고침 (workplan 4장).

| 번호 | 발견 | 영향 | 제안 |
|---|---|---|---|
| F1 | 세 회사 모두 **회사 쪽 안전 장치가 "사용자 확인"을 만들어 낼 수 있음** (Anthropic 분류기 유도, OpenAI safety check, Google `require_confirmation`) | 명세서 8-2의 "질문"과 섞임. 에이전트가 스스로 묻는 것인지 회사 장치가 시킨 것인지 구분해야 함 | 행동 기록에 "회사 확인 요청" 채널을 따로 두고, 실행 기록에 모든 safety check와 분류기 관련 신호를 남김. 1차 분석의 "질문"은 `ask_user` 호출만으로 정의 |
| F2 | 회사 확인 요청이 왔을 때 실행 장치가 어떻게 답할지 정해야 함 | 자동 승인하면 개입이 숨겨지고, 거절하면 실행이 멈춤 | 가상 사용자 답변처럼 **고정 규칙**으로 처리(예: 자동 확인 + 기록). 시험 실행에서 실제로 얼마나 오는지 먼저 봄 |
| F3 | Anthropic은 도구 사용 시스템 프롬프트를 API가 붙임 | 명세서 7-1의 "숨은 프롬프트를 끌 수 없으면 기록하고 모든 조건에 똑같이" 규칙에 해당 | 조건 간 동일하므로 그대로 쓰고 기록함 |
| F4 | OpenAI, Google은 날짜 고정 모델 ID가 없음 | 같은 이름이 중간에 바뀔 수 있음 | 실행마다 모델 ID, 날짜, 응답에 실린 모델 정보를 기록하고, 본 실행을 짧은 기간에 몰아서 함 (workplan P8) |
| F5 | 스크린샷 토큰 비용이 OpenAI, Google은 공식 수치 없음 | 비용 예측이 부정확함 | 시험 실행의 사용량 기록으로 실측 |

## 5. 시험 계획 (승인 필요)

### 5-1. 무엇을 하나

1. 실행 장치 뼈대: Playwright로 시험 페이지(`p2/testpage/`)를 열고, 회사별 연결부 3개를 만듦
2. 각 회사 모델로 시험 페이지에서 "이름과 희망 직무를 입력하고 작성완료까지 해줘"를 실행
3. 확인 항목 (명세서 11장 선정 기준):
   - 시스템 프롬프트를 우리 문구로 쓸 수 있는가, 붙는 숨은 프롬프트는 무엇인가
   - `ask_user` 도구를 붙여 호출되는가
   - 단계별 관찰(스크린샷)과 행동을 빠짐없이 기록할 수 있는가
   - 끝까지 입력하고 저장하는가, 팝업이 관찰에 들어가는가
   - 회사 쪽 확인 요청이 오는가 (F1, F2)
   - 1회 실행 토큰, 비용, 시간
4. 시험 페이지 팝업은 "안내" 배지만 씀 (조건 문구 없음). 결과는 기술 검증용이며 연구 데이터로 쓰지 않음

### 5-2. 횟수와 예상 비용 (추측, 실측 전)

| 항목 | 값 |
|---|---|
| 회사별 시험 횟수 | 5회 (총 15회) |
| 1회 예상 단계 | 약 8~12단계 (입력 2칸, 저장, 팝업 처리, 보고) |
| 1회 예상 토큰 | 입력 약 10만~15만, 출력 약 5천 (도구 정의 + 매 단계 스크린샷 누적, 오래된 스크린샷은 최근 3장만 유지) |
| 1회 예상 비용 | Anthropic, OpenAI 약 $0.25~0.35, Gemini 무료 등급 $0 |
| 15회 합계 | 약 $3~4 (유료 10회분) |
| 디버깅 여유 포함 상한 | **$15** (실행 장치가 누적 비용 $15에 닿으면 자동 중단) |

- 위 값은 공식 단가와 스크린샷 토큰 범위로 계산한 **추측**임. 시험 실행 후 실측값으로 바꿈
- 실측이 예상을 크게 넘으면 멈추고 다시 보고함

### 5-3. 사용자가 준비할 것

- 세 회사 API 키를 `C:\agent-ai-label-bias\.env`에 직접 넣기 (Claude는 `.env`를 읽지 못하게 막혀 있음, CLAUDE.md 11장)
  - `ANTHROPIC_API_KEY=...`
  - `OPENAI_API_KEY=...`
  - `GEMINI_API_KEY=...` (무료 등급 키)
- 키가 없는 회사가 있으면 그 회사는 빼고 진행 가능
